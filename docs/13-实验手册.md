# 13 · 实验手册

> 按阶段做的动手实验，每个实验给出「目标 / 步骤 / 观察点」。
> 前置：全栈已启动（[README](../README.md) 快速开始）。

---

## 实验 0：一键启动全栈

```bash
docker compose up -d --build
docker compose ps    # 所有服务 Up，mysql/nacos 为 healthy
```

**观察点**：启动顺序 `MySQL → Nacos → nacos-config-init → 业务服务 → Gateway`。

---

## 实验 1：Nacos 服务注册

```bash
curl 'http://localhost:8848/nacos/v1/ns/instance/list?serviceName=user-service'
# 控制台：http://localhost:8088 → 服务管理 → 服务列表

docker compose stop product-service
# 等待心跳超时后再查实例列表
```

**观察点**：停服后实例被标记不健康/剔除。

---

## 实验 2：网关路由与 traceId

```bash
curl -i http://localhost:8080/api/users/1
curl -i http://localhost:8080/api/products/1
curl -s http://localhost:8080/actuator/gateway/routes | jq '.[].route_id'
```

**观察点**：响应头含 `X-Trace-Id`，网关日志打印 `cost=...ms`；直接访问 `http://localhost:8081/users/1` 也通。

## 实验 3：真实数据库

```bash
docker compose exec mysql mysql -uroot -proot123456 -e \
  'SELECT id,name,price,stock FROM product_db.products;'

curl -X POST 'http://localhost:8080/api/orders?userId=1&productId=1&quantity=2'

docker compose exec mysql mysql -uroot -proot123456 -e \
  'SELECT id,stock FROM product_db.products WHERE id=1; SELECT order_no,amount,status FROM order_db.orders;'
```

**观察点**：库存从 100 变成 98，`orders` 表新增一行。

## 实验 4：防超卖

```bash
# 商品 2 库存 20，一次买 100
curl -i -X POST 'http://localhost:8080/api/orders?userId=1&productId=2&quantity=100'
# 预期 409 CONFLICT，库存不变
```

## 实验 5：Sentinel 熔断与降级（重点）

```bash
# 基线
curl -X POST 'http://localhost:8080/api/orders?userId=1&productId=1&quantity=1'

# 故障注入
docker compose stop product-service

# 连续下单，观察 fallback
for i in $(seq 1 8); do
  echo -n "$i: "
  curl -s -X POST 'http://localhost:8080/api/orders?userId=1&productId=1&quantity=1' | head -c 120
  echo
done

# Dashboard http://localhost:8090 查看 createOrder 实时监控

# 恢复
docker compose start product-service
sleep 12
curl -X POST 'http://localhost:8080/api/orders?userId=1&productId=1&quantity=1'
```

**观察点**：下游故障后返回 503 降级响应；恢复后半开探测成功回到正常。

